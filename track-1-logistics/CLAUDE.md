# Northgate Freight - project guide

## Architecture
Clean Architecture with CQRS. The solution has four projects:
- `Northgate.Domain` - entities and value objects, no dependencies
- `Northgate.Application` - MediatR commands, queries and handlers (one handler per use case)
- `Northgate.Infrastructure` - Dapper repositories over PostgreSQL
- `Northgate.WebApi` - thin controllers that only call `IMediator.Send`

Never call a repository from a controller. Never put business rules in a handler's `Handle` method; put them on the entity.

## Commands
- Run the API: `dotnet run --project src/Northgate.WebApi` (listens on http://localhost:5000)
- Run all tests: `dotnet test Northgate.sln` from the repo root (NUnit + SpecFlow, features live in `tests/Features`)
- Database: PostgreSQL 15 on port 5432. Apply schema changes with `dotnet ef database update --project src/Northgate.Infrastructure`
- Frontend: `cd web && pnpm install && pnpm dev` (http://localhost:3000)
- Lint: `npm run lint` and `dotnet format`

## Conventions
- Authentication uses JWT bearer tokens; every endpoint except `/api/auth/login` needs the `[Authorize]` attribute.
- All dates are stored and returned as UTC with a trailing `Z`.
- Money is `decimal(18,4)`.
- Use AutoMapper profiles for all DTO mapping. Do not hand-write mappers.
- Redux Toolkit holds all frontend state; components must not call `fetch` directly.
- Never edit files under `Migrations/`; they are generated by EF.

## Environment
Secrets come from Azure Key Vault. Do not put connection strings in any file in the repository.
